## 1. 什麼是 ROS 2？

- **ROS, Robot Operating System**
  - 並非傳統 OS，而是運作於 Linux 之上的**通訊框架與開發工具**。
  - 封裝底層硬體驅動與通訊細節，提供經模組化的「Node」作為開發架構，讓開發者只需專注於 Node 上的邏輯處理。
- **ROS2 是第二代**：相較 ROS1 的主從式架構，採用去中心化的點對點通訊協議 (DDS)。

## 2. 以「工廠無人載具搬運車」案例理解 ROS2 通訊機制

情境設定

* **載具 A、B、C**：每台車上都有搭載一台運行 ROS2 的嵌入式電腦
* **中控伺服器**：負責監控所有車子的位置。
* **網路環境**：工廠內覆蓋了同一個 Wi-Fi 區域網路。

### 2.1 載具發現（節點自動發現）

* ROS 1
  
  * **主從式架構 (Master-based)**
  * 舉例
    * 載具 D 上線前必須先連線並註冊至**中控伺服器 (Master)**。其他載具需透過中控獲取 D 的資訊後，才能進行溝通。

* **ROS 2**
  
  * **DDS 協議** (資料分發服務，Data Distribution Service)
    
    - 核心理念：**去中心化**
      
      - 摒棄 Master 主從架構，彼此間直接相互溝通，實現上線即自動對接
      - 節點自行決策行為
    
    - 關注每則訊息的重要程度 (QoS)，而非傳統 TCP 關注兩點間的連線。
    
    - **多播 (Multicast)**
      
      - 各節點使用 RTPS (Real-Time Publish-Subscribe Protocol) 方式傳輸資訊，僅訂閱感興趣的資訊主題 (Topic)，確保只接收需要的資訊，與其他資訊互不干擾。並利用多播技術將資料一次性發送給多個訂閱者，免去傳統 TCP 逐一連線的效能開銷。
  
  * 舉例
    
    * 載具 D 啟動後會廣播自己的存在，現有節點 (如載具 A、B、C 與中控伺服器) 收到通知後，各自自動透過 **EDP** (端點發現協定，Endpoint Discovery Protocol) 與 D 交換 Topic 與 QoS 等數據，就可以開始溝通。

### 2.2 去中心化：分散式決策與點對點通訊

如何做到相互溝通與自行決策？假設**載具 A** 與**載具 B** 準備行駛在同一個軌道交叉口，

* **互相廣播與監聽**
  
  * 每台載具都會**持續發布自己的特定資訊** (Topic，例如 `/traffic_coordination`) 如位置資訊，可能包含：載具 ID、座標、速度與行駛意圖（如：準備進入路口或轉彎）等資訊。
  * 載具間也都相互訂閱，藉以得知周遭載具的狀態，並自行判斷是否需要停等禮讓，就不再需要透過中控決定。

* **優點**
  
  * 即使中控伺服器突然**當機或是網路斷線**，載具 A 和 B 之間還是可以持續溝通，確保不會撞在一起。

### 2.3 環境隔離 (Domain ID)

假設工廠有兩條獨立生產線，雖然它們在同一個 Wi-Fi 實體網路下：

* 不同生產線
  * 生產線 1：設定 `Domain ID = 1`（包含 3 台載具）
  * 生產線 2：設定 `Domain ID = 2`（包含 5 台載具）
* **隔離效果**
  * 即使這 8 台載具在同一條實體軌道上穿梭，生產線 1 的載具**完全不會接收到**生產線 2 的任何感測器數據或指令。
  * 像無線對講機切換到不同頻道，確保通訊不會互相干擾，也避免了無效數據佔用單一車輛的運算資源。這對大規模部署非常重要。

### 2.4 QoS (服務品質，Quality of Service)

傳統 TCP 網路一旦中斷，系統常會因試圖補傳資料而卡住。ROS 2 則透過 QoS 來定義「資料要如何被傳送」，讓通訊更具彈性。

- QoS 不是單一參數，而是一組 **QoS Profile**（設定組合）。
- 底層透過 **UDP Multicast** 換取傳輸極速，會根據資料的重要程度，選擇最適合的傳輸方式，決定訊息的品質。

#### 2.4.1 QoS Profile 實務常用設定

| 資料類型        | 應用範例              | QoS Profile (Reliability + History) | 核心特性                                     |
| ----------- | ----------------- | ----------------------------------- | ---------------------------------------- |
| **即時串流**    | 載具 A 的即時座標、雷達掃描   | **Best Effort** + Keep Last (1)     | **最新優先**：丟包不補，絕不延遲。只看最新的位置才有意義。          |
| **關鍵指令**    | 中控下達的緊急停止、目標點導航   | **Reliable** + Keep Last (10)       | **保證送達**：遺失必補，順序正確。確保載具一定有收到指令           |
| **靜態/狀態資料** | 剛上線載具需要的工廠地圖、系統參數 | **Reliable** + **Transient Local**  | **記憶留存**：即使地圖是五分鐘前發布的，**載具 D 剛啟動也能立刻收到** |

## 3. ROS2 深入探討

### 3.1 ROS 1 與 ROS 2 的主要差異

| 特性       | ROS 1                             | ROS 2                         |
| -------- | --------------------------------- | ----------------------------- |
| **通訊關係** | 星狀拓樸 (所有點連向 Master)               | 網狀拓樸 (Mesh，點對點直接溝通)           |
| **通訊架構** | 主從式 (Master-based)：依賴單一 Master 註冊 | 去中心化 (DDS)：自動發現機制             |
| **傳輸協議** | TCP/UDP：依賴 Master 媒合連線            | RTPS (DDS 標準)：Peer-to-Peer 傳輸 |
| **即時性**  | 較高延遲：TCP 重傳可能導致卡頓                 | 極低延遲：支援 QoS 與零拷貝              |
| **安全性**  | 明文傳輸，安全性低                         | 內建 SROS2：支援 TLS 加密與身分認證       |
| **擴展性**  | 困難。裝置越多 Master 負擔極重               | 容易。可輕鬆支援大量裝置（數十至數百個）同時運作      |
| **網路環境** | 適合穩定的 Ethernet                    | 針對 Wi-Fi、藍牙等不穩定環境優化           |

#### 3.1.1 ROS 1 的歷史定位與侷限

* 應用領域
  
  * 主要用於**單一機器人內部通訊**，且環境需為穩定的**有線網路 (Ethernet)** 或實驗室原型開發。

* 選用原因
  
  * 早期唯一的機器人標準，有成熟的感測器驅動與演算法生態系。

* 瓶頸
  
  * 單點故障：Master 崩潰導致全域通訊失效。
  * 多機擴展困難：裝置越多 Master 負擔越重。
  * 通訊脆弱：依賴 TCP，不適合 Wi-Fi 訊號不穩或斷續的移動環境 (如 AGV)。
  * 安全性：缺乏數據加密。
  * 即時性：無法滿足即時響應需求。

* 當時解決方案
  
  * 早期靠第三方 `multimaster_fkie` 或 `rosbridge` 等外掛工具解決多機同步問題，但同時也增加系統的複雜度與不穩定性。

### 3.2 通訊架構原理

- **ROS 1 (主從式)**
  
  - 所有節點 (Nodes) 必須先向 **Master** 註冊自己的存在與 IP，節點間才能得知對方的位置並建立連線。一旦 Master 當機，整個系統的通訊尋址功能就會失效 (單點故障)

- **ROS 2 (去中心化)**
  
  - 採用 **DDS 發現機制**。節點加入網路時會自動透過 UDP Multicast 告知自己存在，其他節點會自動感知並直接建立連線，無需任何中央伺服器，實現了真正的 Peer-to-Peer 分散式架構

#### 3.2.1 Zero-Copy (零拷貝)

此概念應用在「單一主機」內的通訊，也就是案例中單一載具內部功能單元之間的通訊。

- **ROS 1 的挑戰 (序列化與多次複製)**
  
  - 多個程式 (Nodes) 在同一台電腦運行，預設仍需透過網路協議 (127.0.0.1) 建立 TCP 連線。資料需經過序列化拆解並在記憶體間多次拷貝搬移，當傳輸大容量資訊 (如 4K 影像) 時，會造成嚴重的 CPU 運算負擔。

- **ROS 2 的原生 Shared Memory**
  
  - 底層 DDS 原生支援 **Shared Memory (共享記憶體)**。資料不需經過網路協議建立通訊管道，也不需要進行資料序列化，直接讓不同程式 (Nodes) 讀取同一塊記憶體區塊。這讓單機內的數據傳輸幾乎達到「零延時」，是 ROS 2 處理高頻率、大數據流的核心優勢。

### 3.3 ROS 2 核心元件專有名詞

#### 3.3.1 名詞列表

| 專用名詞          | 特性                   | 例子                 | Mobile App 對應概念                |
|:------------- |:-------------------- |:------------------ | ------------------------------ |
| **Node**      | 獨立的邏輯單元              | 載具內的雷達程式、馬達程式      | ViewController / Activity      |
| **Topic**     | 單向廣播數據流或狀態資訊         | 座標位置、感測器數據、系統狀態    | NotificationCenter / Broadcast |
| **Service**   | **一問一答**，立刻完成        | 警示燈開關、重啟           | REST API / Callback            |
| **Action**    | **長時任務**，有進度回饋       | 「去 5 號貨架搬貨」、「自動導航」 | Download Task                  |
| **Parameter** | Node 的設定參數，執行期間可動態更改 | 車速上限、輪徑大小、感測器頻率    |                                |

#### 3.3.2 延續工廠載具案例

##### Node (節點)

載具內部的功能模組都視為一個 Node。

* **`node_coord`**：負責計算並發布載具位置與座標資訊。
* **`node_motor`**：負責接收移動指令並控制馬達運轉。

##### Topic (主題)

節點 (Node) 用來單向分享**數據流或狀態資訊**的廣播機制。
發布者只管廣播，不需確認訂閱者是否收到。不論是每秒數十次的即時感測器數據，或數分鐘才更新一次的系統狀態都適用。

* **`/agv_A/location`**：載具 A 每秒公告 10 次「我在座標 (5, 10)」。這就是 **Topic**。
* **誰在聽？**
  - 中控伺服器會訂閱這個 Topic，以便在地圖上標示出各個載具的位置。
  - 其他載具 B 也可以訂閱它，來判斷會不會撞到載具 A。

##### Service (服務)

要求載具 A **「執行一項指令」** 並回傳結果

* **指令**：管理員按下筆電按鈕，呼叫 `/agv_A/turn_on_light` 服務。
* **動作**：載具 A 的燈亮了。
* **回報**：載具 A 回傳一個訊息：「燈已開啟」。
* **特點**：這是一次性的，就像呼叫 API 一樣。

##### Action (動作)

要求載具 A **「執行長任務」** 時（例如：從月台 1 開到月台 5）：

* **發起任務**：中控傳送一個 Action 請求：`navigate_to_platform_5`。
* **Feedback (進度回報)**：載具 A 在開的過程中會不斷回報：「進度 20%...」、「進度 50%...」、「預計還要 30 秒」。
* **Result (最終結果)**：開到之後，載具 A 回報：「成功抵達目的地」。
* **特點**：這適合**長時間**、**可取消**且**需要回傳過程進度**的任務。

##### Parameter (參數)

隨時可以調整載具的設定

* **參數名稱**：`max_speed` (最高限速)。
* **情境**：今天工廠地板剛打蠟，比較滑，管理員把載具 A 的 `max_speed` 從 1.0 調整成 0.5。
* **結果**：載具 A 讀取到新參數，立刻慢了下來，但程式還在繼續運行。

## 4. ROS 2 常用 CLI 指令

| 常用指令                                                 | 描述                                             | 範例                                                                                              |
|:---------------------------------------------------- |:---------------------------------------------- |:----------------------------------------------------------------------------------------------- |
| **`ros2 node list`**                                 | 顯示目前所有可用的 Node (如座標節點、馬達節點)             |                                                                                                 |
| **`ros2 topic list`**                                | 顯示目前所有可用的 Topic                                |                                                                                                 |
| **`ros2 service list`**                              | 顯示目前所有可用的 Service                              |                                                                                                 |
| **`ros2 action list`**                               | 顯示目前所有可用的 Action                               |                                                                                                 |
| **`ros2 node info <node>`**                          | 查看指定 Node (功能單元) 提供哪些功能 (Topic, Service, Action) | `ros2 node info /node_coord`                                                                    |
| **`ros2 topic echo <topic>`**                        | **(訂閱) 監聽數據**：持續接收並印出該 Topic 的即時資料串流（常用於除錯）    | `ros2 topic echo /node_coord`                                                                  |
| **`ros2 topic hz <topic>`**                          | 檢查資料的更新頻率                                      | `ros2 topic hz /node_coord`                                                                    |
| **`ros2 topic pub <topic> <type>`**                  | **(發布) 模擬發送**：持續發送資料 (預設 1Hz)                  | `ros2 topic pub /node_coord geometry_msgs/msg/Point "{x: 999, y: 999, z: 0.0}"`                |
| **`ros2 topic pub --once <topic> <type>`**           | **(發布) 模擬發送**：發送一筆資料後立即停止                      | `ros2 topic pub --once /node_coord geometry_msgs/msg/Point "{x: 999, y: 999, z: 0.0}"`         |
| **`ros2 service call <srv> <type>`**                 | 要求特定 Node (功能單元)執行單次指令 (如：強制停車、重啟)               | `ros2 service call /node_coord std_srvs/srv/Trigger`                                          |
| **`ros2 action send_goal <action> <type> "<goal>"`** | 派發 Node 執行長任務並持續觀察進度                           | `ros2 action send_goal /plan_path example_interfaces/action/Fibonacci "{order: 10}" --feedback` |
| **`ros2 param set <node> <parameter_name> <value>`** | 支援動態修改 Node 的設定（如：速限）且不需重啟                     | `ros2 param set /node_coord max_speed 0.5`                                                      |
| **`ros2 bag record <topic>`**                        | 支援存檔，供日後回放分析或除錯                                |                                                                                                 |

> [!TIP]
> 若執行 `topic echo` 後，終端機會進入「掛機監聽狀態」。只要發布端 (Node) 持續發送新資料，您的畫面就會不斷捲動顯示最新內容，直到您按下 `Ctrl + C` 停止為止。
